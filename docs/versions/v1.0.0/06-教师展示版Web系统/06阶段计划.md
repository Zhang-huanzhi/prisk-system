# 06 阶段：单 PR 代码审计工作区

## 目标

把 03、04、05、07 阶段的真实 NetBox PR 产物接入可交互看板，明确以一次冻结 PR 作为分析单位。PR 列表只承担导航，当前 PR 进入独立工作区，展示概览、统一 Diff、规则证据、代码定位和当前 PR 评分重算。本阶段对应冻结样本模式；本地项目的 base/head 分支审查在 08 阶段补充。

## 技术选择

- Next.js 16、React 19、TypeScript、Tailwind CSS 4；
- Python 标准库 `http.server` 提供只读演示 API；
- 不引入数据库，不修改阶段 JSONL，不依赖网络数据；
- 复用 EiheiZone-experience 的技术栈和视觉语言，采用 PR 信息头加标签页的工作区布局。

## 展示功能

- PR 抽屉搜索、场景筛选和风险等级筛选；
- 概览、代码变更、风险规则、评分配置四个标签页；
- 03 阶段统一 Diff 的文件、Hunk、增删/上下文行、行号和文件状态；
- 四类规则目录完整公开显示触发条件、证据类型、适用范围、复核建议、限制和默认权重；
- 规则命中展开到文件、节点类型、结构变化、限定名和 Diff 行，点击证据定位到对应代码；
- 当前 PR 的评分配置、测试协同提示和 JSON/Markdown 报告导出；
- API 分层为轻量 `/api/dataset` 导航、单 PR `/api/pr/<number>` 详情和单 PR `/api/analyze` 重算。

## 固定边界

- 看板只使用冻结的阶段 JSONL，不重新计算 Diff，不修改 03 至 07 阶段原始产物；
- 代码审计展示统一 Diff，不加载完整仓库源码；
- 评分只表示人工复核优先级，不表示缺陷概率，也不自动确认缺陷；
- 当前仍是离线样本与教师演示工具，不是在线 GitHub 审查系统。
