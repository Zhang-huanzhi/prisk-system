# 01 阶段：项目调研与范围

## 调研目标

本阶段从公开后端项目的已合并 Pull Request 中确认可恢复、可解析且具有代表性风险场景的实验对象。调研只用于明确系统研究范围，不归档个人开题报告、学院材料或答辩过程文件。

## 项目选择

- 主实验项目：`netbox-community/netbox`。
- 对照项目：`saleor/saleor`。
- NetBox 冻结抽样 120 条 PR，其中 99 条包含可分析的业务或测试 Python 变更，21 条因缺少目标范围代码变更而排除。
- Saleor 试采样 40 条，其中 36 条可分析；保留为项目比较依据，不作为后续规则引擎的正式输入。

NetBox 的选择依据是四类候选场景均有重复样本、样本规模足以支持后续规则实现。审查评论、CI 和合并后修复证据不完整，因此不把标签质量或审查严格程度作为选型结论。

## 冻结研究范围

纳入接口行为、认证与权限、数据与事务、配置与异常四类场景。测试是否与业务变更协同修改作为辅助证据，不单独构成风险类别。研究目标是定位需要人工复核的结构线索，不自动确认缺陷，也不估计缺陷概率。

调研样本、汇总、采样脚本及场景统计见本阶段的 [02 阶段样本与场景材料](../02-PR采样&定风险场景/README.md)。
