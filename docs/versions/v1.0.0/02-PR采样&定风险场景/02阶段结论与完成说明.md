# 02 阶段结论与完成说明

## 1. 阶段目标

本阶段通过公开后端项目的已合并 PR 试采样，确认主实验项目、可分析样本和能够稳定识别的风险场景，为后续规则引擎实现冻结输入范围。

本阶段不要求覆盖所有后端风险，也不把代码中出现某类变化直接等同于已经确认存在缺陷。采样记录中的变更事实与评价证据分开保存：变更事实用于确定规则输入，评价证据只用于后续对照和边界分析。

## 2. 项目决定

```text
主项目：netbox-community/netbox
对照项目：saleor/saleor
查询日期：2026-10-28
```

NetBox 被确定为主项目，原因是其样本量和风险场景覆盖更适合支撑规则引擎研究。Saleor 的采样结果保留，用于说明项目选择依据，并在后续需要时讨论规则向相近后端项目迁移的可能性。

## 4. 纳入的风险场景

四类场景均在可分析样本中反复出现，且包含多种结构信号，纳入后续规则范围。

| 风险场景 | 可分析 PR | 主要信号 | Python 解析成功率 |
| --- | ---: | --- | ---: |
| 接口行为 | 45 | REST API、GraphQL 路径 | 95.6% |
| 认证与权限 | 26 | 权限差异、权限路径、users 应用 | 100% |
| 数据与事务 | 44 | 模型、迁移、atomic 或 rollback | 93.2% |
| 配置与异常 | 38 | settings、configuration、异常模块 | 92.1% |

测试协同不占用四类规则场景名额。99 条可分析 PR 中有 48 条同时修改测试，测试是否协同修改将在评分阶段作为辅助证据。

## 5. 评价证据与限制

99 条可分析 PR 中，20 条可以把审查评论对应到之后修改过的文件，67 条没有这种可用评论，12 条评论无法对应到后续文件。CI 结果只有 12 条仍可取得，合并后修复只有 1 条能从标题确认。因此，本阶段不使用这些证据直接定义规则命中，也不据此声称 NetBox 的审查标签更可靠。

本阶段使用 Python 标准库 `ast.parse` 检查目标版本上的 Python 文件。该检查只说明语法可解析，框架级结构对齐和业务语义判断留到后续规则设计阶段。

## 6. 当前规则边界

后续规则引擎只针对能够由代码结构、变更关系、框架约定或局部数据流直接支持的风险线索。当前纳入：

1. 接口行为；
2. 认证与权限；
3. 数据与事务；
4. 配置与异常。

暂不在本阶段规则范围内：

- 复杂业务需求和整体方案是否正确；
- 仅依赖运行环境才能发现的并发、性能和资源问题；
- 完整的分布式时序和第三方服务故障行为；
- 需要大量业务上下文才能判断的语义风险。

这些问题可以作为人工复核提示、案例分析或后续机器学习和 LLM 扩展方向，但不能作为当前规则引擎已经覆盖的能力。

## 7. 完成判定

02 阶段已完成，判定依据如下：

- 主项目已确定为 NetBox，对照项目已确定为 Saleor；
- 120 条 NetBox 样本、99 条可分析样本及 21 条排除样本已经冻结；
- 所有样本的 `base_sha`、`head_sha` 和差异可恢复记录完整；
- NetBox 仓库已确认不是浅克隆；
- 场景表、JSON 摘要和本结论中的数量一致；
- 四类纳入场景和测试协同的辅助地位已经明确；
- 评价证据不足的限制已经记录；
- 本阶段不再扩大采样或重新选择项目。

## 8. 交接到 03 阶段

下一阶段只处理 NetBox，使用本阶段冻结的 JSONL 和四类风险范围，建立 PR 数据基础设施与统一变更表示：

```text
PR 元数据
→ base/head 版本
→ 累积 Diff
→ 业务文件与测试文件
→ 统一变更对象
```

03 阶段不再重新选择项目或重新统计风险场景，重点转为差异读取、文件角色识别、结构解析输入和后续规则匹配所需的数据接口。

## 9. 归档验证

- NetBox 样本 120 条，Saleor 对照试采样 40 条；两份 JSONL 均保留公开仓库、PR 编号、提交 SHA 和评价字段，并移除贡献者账号字段。
- NetBox 与 Saleor 汇总和场景统计见 [`artifacts/`](artifacts/)；采样脚本按相对目录定位输出，不包含本机绝对路径或凭证。
- 本阶段验收基于冻结样本与场景统计，不存在独立自动化测试日志，也不代表规则有效性验证。
