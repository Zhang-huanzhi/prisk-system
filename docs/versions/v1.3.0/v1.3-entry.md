## 阶段定位与承接

v1.2.0 核心规则实现与三态引擎能力闭环已归档于 [docs/versions/v1.2.0/](../v1.2.0/README.md)。

本阶段严格承接 [开发推进大纲](../../standards/development-roadmap.md) 中的 **「v1.3.0 动态交互工作台与报告」** 核心目标（知识库中 2 张延后草稿卡片 `workflow.large_change_scope` 与 `data.django_transaction_boundary_changed` 按 [结构可行性筛选](../../rules/structural-feasibility.md) 保持 `draft` 不变）：

1. **运行时配置解耦**（Task 026）：
   - 规则启用开关（`enabled_rules`）、启发式权重（`rule_weights`）、风险分段阈值（`thresholds`）与规则内部判定参数（`rule_thresholds`）全面解耦；
   - 支持针对不同审查场景（均衡基线、安全加固、框架升级、日常合规、历史兼容基线）载入不同配置预设（Presets）。
2. **快照局部重跑机制**（Task 027）：
   - 复用已提取并缓存的 Git 三点 Diff（Stage03）与 Python AST 结构对象（Stage04）；
   - 在用户调整规则开关、权重或阈值时，按三级重跑机制（`full_run` / `stage05_rules_rerun` / `stage07_rescore_only`）复用上下文，仅局部重跑受影响阶段。
3. **Web 看板交互增强与审查报告固化**（Task 028）：
   - 前端看板完整支持 29 条规则三态明细筛选、5 套场景预设切换、规则内部阈值调节、局部重跑状态徽标与 Gatekeeper 抬升事实展示；
   - 导出可交互/离线审查报告（Markdown/JSON），**报告强制固化本次运行的完整配置快照**（预设、SHA-256 指纹 `config_digest`、开关、权重、阈值及可复现配置 JSON 载荷），确保任何一次审查结论完全可追溯、可复现。
4. **前端工作台 GitHub Primer 风格重构与交互布局优化**（Task 029）：
   - 解决左侧栏长路径与长分支名溢出穿透截断问题；
   - 左侧栏常驻 29 条规则目录导航树，支持搜索、终态筛选与规则卡片侧边抽屉查阅；
   - 顶栏与 PR 概览整合为 GitHub PR 双层头部结构；
   - 全面引入 GitHub Primer 色彩排版体系，提升字体明度对比与可读性；
   - 代码变更重构为「左侧 Sticky 层级目录树 + 右侧多文件连续 Diff 卡片流 + `Viewed` 已审阅跟踪 + 证据行高亮定位」。

## 阶段成果与收口

1. **运行时配置解耦与场景预设体系（Task 026）**：确立 `config.v1` 契约，内置 5 套标准化场景预设，支持规则内部判定阈值（`max_depth`、`min_length`）动态注入，新增 `/api/config/presets` 端点，且在 `legacy_baseline` 下保持 10 分分母与历史快照 100% 兼容。
2. **三级快照局部重跑机制（Task 027）**：建立 LRU 线程安全快照缓存 `AnalysisSnapshotCache`，实现 Tier 0（`full_run`）、Tier 1（`stage05_rules_rerun`）与 Tier 2（`stage07_rescore_only`），报表输出诊断元数据 `snapshot_meta`。
3. **可复现配置快照固化与报告导出（Task 028）**：确立 `config.snapshot.v1` 与 16 位确定性 SHA-256 指纹 `config_digest`，实现 Markdown 审查报告渲染器 `render_markdown_report`，报告导出强制封存配置快照与可复现载荷，打通前后端预设与阈值交互。
4. **前端工作台 GitHub Primer 风格重构（Task 029）**：全面升级对比度色板，左侧常驻 29 条规则目录树并支持卡片抽屉，重构 Files Changed 为 Sticky 目录树与连续 Diff 卡片流，引入 `Viewed` 已审阅跟踪与行级高亮定位。
5. **阶段归档**：Task 030 完成本阶段资产冻结归档，正式建立 `docs/versions/v1.3.0/`，并将后续演进交接至 `v1.4-entry.md`。
