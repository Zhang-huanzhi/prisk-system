# NNN：任务标题

## 目标

用一两段说明本任务要完成什么，以及它承接哪份入口或前序任务。只写本任务的目标，不预写验收或合并安排。

## 范围

列出本任务要做的事项。

## 不做事项

列出明确排除的工作。只写本任务范围内的排除项。

## 设计

说明方案要点。尚无设计时保留本节并填写「待填写」。

## 实现

说明将改动的位置。文档任务写文档路径；实现任务写代码、配置与测试路径。

## 验证

列出将执行的检查（例如 `git diff --check`，以及若改动代码则要跑的测试命令）。完成后把实际结果补在这里。

## 生命周期增量

（可选）若本任务改动规则生命周期，用表格列出 `rule_id`、改前状态、改后状态。无此项则删除本节，不要填虚构的规则 ID。

## 残余风险

列出仍未关闭的限制、已知漏报，或需要后续任务处理的事项。
