# 大规模变更范围

| 字段 | 内容 |
| --- | --- |
| 规则 ID | `workflow.large_change_scope` |
| 版本 / 阵营 / 生命周期 | `v1` / `breaking_impact` / `draft` |
| 负责人 | `Prisk-System` |
| 风险性质 / 依赖层级 | `pr_intrinsic` / `process` |
| 适用范围 | 跨语言 PR；模块映射和排除规则由项目配置 |
| 分析目标层 / 证据形态 | `change_metadata`, `diff_delta` / `metric_value`, `code_slice` |
| 严重度 / 一票抬升 | `Medium` / `false`，条件 `null`；设计值待验证 |

## 制定理由

审查范围涉及大量变更行、文件或模块时，理解和复核可能更困难。可用计数提醒审查者关注范围，但计数不是实际影响半径、变更熵或缺陷概率。自动生成代码、机械重命名等可能放大计数；`breaking_impact` 是登记阵营，不表示已证实破坏。

## 检测定义

- 对象：PR 三点 Diff 及项目模块映射；分别统计新增加删除行数、变化文件数，以及已分类文件所属不同模块数。
- 触发方案：完整输入且相关项目阈值已配置时，`changed_lines >= lines_threshold`、`files_changed >= files_threshold`、`modules_changed >= modules_threshold` 任一成立则提示；报告具体超限项。模块阈值仅在映射完整时参与计算。
- 不触发：可用指标均低于已配置阈值；阈值未配置、Diff 不完整或模块映射不可用时该指标标记未评估，所有指标均未评估时规则标记未分析。阈值当前均待确定，不能据此产生运行 Finding。
- 特征（拟定）：`changed_lines`（新增行 + 删除行，integer，`gte`，阈值待确定）；`files_changed`（去重后文件数，integer，`gte`，阈值待确定）；`modules_changed`（映射后去重模块数，integer，`gte`，阈值待确定）。文件重命名计一次；二进制文件无行数时需单独标明。自动生成文件、锁文件、`fixtures/` 数据文件、`migrations/` 和纯重命名是否排除由项目显式配置并记录，默认不排除；同时保留原始总计、过滤后计数和各类文件贡献。迁移文件可能包含真实数据与部署风险，规模统计的排除配置不能关闭破坏性迁移等其他规则。
- 输入与输出：完整 Diff、文件状态、模块映射和阈值配置；Finding 应包含各计数、阈值、文件或模块清单、排除项与未评估项。没有调用关系时不推断传播路径或影响范围。

示例：某项目明确配置文件阈值为 10，完整 Diff 命中 12 个计入文件时触发；同样配置下仅 2 个文件且其他可用指标均未超限时不触发。此数值仅用于解释条件，不是推荐阈值。

## 理论与项目依据

- Hassan, A. E. (2009). *Predicting faults using the complexity of code changes*. ICSE. [DOI: 10.1109/ICSE.2009.5070510](https://doi.org/10.1109/ICSE.2009.5070510)。论文基于六个开源项目的历史变更过程，研究过程复杂度指标与故障预测；支持研究变更分布，但历史 Change Entropy 不等于单个 PR 模块数或行数，不支持在此预设指数关系。核对范围：Crossref 书目与 OpenAlex 摘要；公式与完整适用范围待阅读全文。
- Sadowski, C., Söderberg, E., Church, L., Sipko, M., & Bacchelli, A. (2018). *Modern code review: a case study at Google*. ICSE-SEIP. [DOI: 10.1145/3183519.3183525](https://doi.org/10.1145/3183519.3183525)。摘要报告通过访谈、调查和大量审查日志研究 Google 的代码审查实践；支持将审查过程作为研究场景，不能从摘要推出通用的 200 行阈值或因果结论。核对范围：书目与摘要。

## 限制与反例

大规模机械替换、fixtures 数据或格式化、迁移文件及生成文件可能使少数文件主导行数统计，并不必然反映业务逻辑复杂度；这些文件也可能承载真实风险。小规模但影响核心调用的变更可能漏报。模块数量取决于项目映射，跨仓库影响和动态调用不在统计范围；规则不测真实爆炸半径、不计算历史变更熵、不直接断言缺陷、回滚或风险概率。需人工复核变更性质、模块关系和部署上下文。

## 有效性计划

011 的结构可行性把本规则列为延后：阈值和模块映射仍未指定，不能用一个临时数字产生 Finding。详见 [结构可行性筛选](../../structural-feasibility.md)。下面的验证计划不因此变成已经执行的结果。

`literature_inherited` 表示研究动机有文献依据；阈值与指标组合需要本项目实证。先构造行数、文件、模块、重命名、二进制、单文件大量 fixtures、迁移文件、排除项、未配置阈值和不完整 Diff 样例，检查原始及过滤后统计；再以冻结 NetBox PR 的已定义审查需求人工标注为判定依据，报告计数分布、阈值敏感性和排序效果，并比较包含及排除相关路径的结果。维护者评论或标签可作为待核实的弱标注线索，但补测请求不能直接证明变更规模过大；须人工交叉标注并报告分歧。历史缺陷或回滚可作为独立的探索性结果，需明确数据质量、观察窗口和混杂因素；`>=3` 模块、200 行和任何效果值均未确定。
