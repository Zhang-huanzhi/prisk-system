# v1.1 卡片门槛决策

本页供所有者在过目卡片之后，决定是否收口 v1.1.0 的**设计范围**（卡片门槛），或把收口延后。本页是决策记录，不是检测器实现，也不是版本冻结声明。

014 的 [v1.1 卡片就绪核对](v1.1-card-readiness.md) 保留为当时的就绪核对范围；本页才是「门槛是否够」的收口位。本页不修改任何 `rules[].lifecycle`，不接入检测器，不建立 `docs/versions/v1.1/` 或 `docs/versions/v1.1.0/`。

**诚实声明：** 本页不改变登记册或卡片的生命周期字段。任务 Accepted ≠ 版本冻结。即便本任务以后被接受，也不自动等于宣布 v1.1.0 完成。

## 2. 所有者过目清单

下列项请对照卡片、[已知框架基类映射](known-framework-bases.md)、登记册与模板逐项过目。本清单不代替打开卡片正文。

1. **已知框架基类映射**
   仅三行：`PrimaryModelSerializer`→`ModelSerializer`，`NetBoxModelViewSet`→`ModelViewSet`，`NetBoxModel`→`Model`。匹配是最后一段整段相等。`RackBaseSerializer`、`restrict_queryset`、表外名字仍 Unanalyzed。映射不是运行时继承解析。

2. **一票抬升（gatekeeper）**
   - 破坏性：`DeleteModel` / `RemoveField` 条件是否与卡片触发面一致；`RunSQL` 不抬升是否可接受。
   - 权限降级：`AllowAny` 与空列表/空元组；是否仍拒绝把自定义权限类「强弱全序」写进 Hit。

3. **非空 + `default=`**（`data.django_non_null_constraint_tightened`）
   已有模型上非空且看不见 `default=` 才是设计 Hit；看见 `default=` 是 NotFound；不能只因 `AddField` 省略 `null=True` 就 Hit。

4. **敏感配置方向**（`config.django_sensitive_settings_changed`）
   放宽/不安全方向 → High Hit；收紧 → NotFound；方向读不出 → Unanalyzed。一票抬升仍为 `false`。

5. **`Meta.fields` / `unsupported_stage04_details`**
   删除规则写明列表成员变化的设计 Hit；当前结构对象读不出嵌套 `Meta` 字符串列表时记缺口原因，**不**把缺口当成 NotFound。核对相关 API 卡片与登记册措辞是否一致。

6. **`Path.open`：设计 vs 检测器**（`code.unmanaged_open`）
   卡片合同含未作为 `with` 上下文的 `Path(...).open(...)`；运行时仍只认直接名称 `open`。确认「合同领先检测器」可接受，并列入 v1.2 跟进。

7. **裸 `except` vs `except Exception`**（`code.bare_exception`）
   设计 Hit 只保留裸 `except:` 与 `except BaseException`；`except Exception:` 不是本规则 Hit。运行时仍把三者放在同一 Finding。确认拆分留给检测器后续任务。

8. **`workflow.large_change_scope`**
   现行严重度 `High`、风险性质 `pr_intrinsic`（015 临时判断，非终局）；阈值仍未指定；`lifecycle` 仍 `draft`。

9. **模板对齐**
   26 张活动卡片是否都按 [规则说明卡片模板](rule-card-template.md) 的标题、两表、第 3/5/6/7 节固定槽写完；过程性标题是否已退出正式正文（017 范围）。

10. **仍无卡片的三条排除项**
    是否继续「有意不写卡片」，而不是永久禁止以后写。

### a) 卡片门槛是否足以冻结 v1.1.0 的设计范围？

| | |
| --- | --- |
| 可选 | `yes` / `not yet` / `yes with carve-outs` |
| **提案** | **`yes with carve-outs`**：设计合同（比较单位、身份、排除、终态边界、模板格式、两处一票抬升条件、已知框架基类映射三行）在 014–017 之后已可过目收口；但检测器与合同不一致处、阈值未指定的大规模变更、以及 016 六张草稿上的未决设计（信号 / 查询集 / `assert` 等）必须以 carve-out 形式明确「设计已写、实现未齐 / 仍可修订」，不得解读为运行时已就绪。 |
